# Compact Gemini comparison references

The latest website test returned HTTP 400 `INVALID_ARGUMENT` without identifying the rejected field. Offline review found that the response schema embedded 2,563 characters of quoted-source enum JSON; the complete schema was 3,094 characters. This is a compatibility risk, not a proven diagnosis. Google's [structured-output documentation](https://ai.google.dev/gemini-api/docs/structured-output) explains that schema complexity can cause request rejection. The provider's generic error does not establish that this particular request exceeded a documented limit.

For Gemini comparisons containing more than 512 excerpt characters in total, or more than 512 characters of potential correction sentences, the adapter now uses a compact reference response. The threshold is our engineering policy, not a Google quota or documented schema limit. Short existing comparison requests, Groq and legacy Ollama keep their previous format. The provider is still selected explicitly and all inference still routes through Bifrost; there is no automatic provider switch or retry.

The model receives the full original excerpts, URLs, dates, claim and a bounded list of corroborated correction candidates as untrusted context. It returns only ordered source IDs and evidence-relation labels, plus a correction candidate ID or `none`. Long excerpts and correction texts are absent from schema enums. Candidate selection is limited to the first eight complete sentences present in at least two excerpts and different from the claim; this can omit a valid correction. Choosing none is always allowed. The complete prepared context remains bounded to 10,000 characters.

Strict Zod validation rejects additional quote/URL/claim fields, missing or reordered/repeated IDs, unknown labels and unknown correction candidates. The backend attaches the entire original excerpt for each validated ID, and maps the correction ID to its complete original sentence and exact source references. Existing comparison validation then checks dates, source grouping, overlap, relevance, scope, agreeing relations and corroborated corrections. Choosing a source ID does not prove semantic entailment. A failed mapping or check still produces inconclusive, no correction and no retry.

This is an internal wire-format adaptation. The public comparison/analysis report is unchanged, including exact original quoted citations. It avoids model transcription errors by attaching quotes in trusted code rather than asking the model to regenerate long passages. Other supplied adapters and short-format comparison requests retain their existing full-quote checks.

For the saved three-source Python example, offline construction now produces a 459-character schema with no source passages embedded in it. The original live record is preserved; `.local/live-website-check/compact-schema-review.json` records this offline inspection. HTTP 400 now receives an explicit parameter-rejection message rather than a generic upstream-failure explanation. This does not disclose raw provider bodies or credentials.

No new live model request has validated this format, and no successful factual verdict is claimed. A separately authorized one-Gemini comparison could reuse the saved evidence without a new Tavily search. Its result could still be inconclusive because excerpt sufficiency and semantic correctness remain necessary.

Offline validation on November 3, 2026 passed all 433 tests across 33 files using one worker, lint, TypeScript, six fixture regressions, production build and API smoke checks. Eleven new cases cover schema size, exact quote/correction reconstruction, unknown/omitted/reordered/repeated references, additional invented quote fields, correction choice/context limits, integration with existing verdict validation and safe HTTP 400 diagnostics without retries. The saved real excerpts were used only to inspect schema construction, not to claim a simulated factual verdict. Actual `.env` was unchanged; zero Gemini or Tavily requests were made.
