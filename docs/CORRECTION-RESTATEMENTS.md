# Restatements are not replacement facts

The historical benchmark produced a source-backed correction validation failure. The original raw model content was not retained, so the exact offending response is unknown. Offline inspection found a reproducible risk: both sources shared `The upstream project confirms [the original claim]`, and the correction schema offered that sentence as a replacement because it differed textually from the claim. A model could select it despite otherwise supporting the claim; the previous validator would then reject the whole response because corrections required contradicting source assessments.

Correction candidate generation now uses one shared helper for both full-quote and compact-reference formats. It excludes literal restatements and narrowly recognized `The upstream project/official announcement/report confirms/states [that]` prefixes. Matching preserves case and all substantive wording; only NFC normalization, whitespace and final punctuation are normalized. It does not remove negation, dates, conditions, arbitrary attribution or qualifications, and it does not perform semantic equivalence inference. A changed date or amount remains a possible correction if fully corroborated.

Both prompts explicitly require no correction for supported/inconclusive assessments or an unchanged claim. When no real replacement candidate exists, the full-quote schema requires null and the compact schema permits only correctionId `none`. Original source passages, URLs, dates and references are unchanged.

For supplied adapters or responses that still propose a redundant correction, backend handling first validates unique known source IDs, eligible distinct groups and the exact complete correction sentence in every cited original excerpt. Only after those checks can a source-backed restatement be omitted while preserving an otherwise supported or inconclusive assessment. The result explains that it was omitted. An invented/rewritten sentence, changed quote, unknown/duplicate reference or insufficient corroboration still rejects the response. A contradictory outcome paired with a correction that merely repeats the claim also rejects the response as inconsistent.

Genuine corrections retain their existing requirement for eligible contradicting source assessments, matching complete sentences and at least two source groups. No date/scope/authority check, currency guard, model budget or no-retry policy is relaxed by this change. Supported historical claims continue to show unknown freshness rather than current support.

Offline tests reproduce the old failure with a constructed response, validate both schema formats, preserve supported/inconclusive outcomes only for fully checked restatements, reject malformed or inconsistent outputs, and retain a genuine source-backed date correction. A separate simulated replay using the saved fictional historical evidence is stored in ignored `historical-restatement-offline.json` beside the benchmark snapshot. It does not reconstruct the original model output or update any live score. The original benchmark's historical validation failure remains recorded until a separately budgeted real check establishes otherwise.

Validation on November 4, 2026 passed all 517 tests across 42 files using one worker, lint, TypeScript, six existing fixture regressions, all 14 simulated pipeline scenarios, production build and API smoke checks. Fourteen new regression cases were added. No Gemini/Tavily requests were made and saved `.env` was unchanged. This step establishes offline behavior only, not real-model confirmation of the historical benchmark case.
