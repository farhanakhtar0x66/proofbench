# Relevant source passages and quality warnings

General retrieval previously sent the first 1,200 characters of each Tavily result. It now selects a continuous passage within returned text using conservative claim anchors. This is local text processing: no extra search, page fetch, extraction inference or provider fallback is introduced. The existing basic-search cap, cache, three-result limit and model budgets remain unchanged.

Short results of at most 1,200 nonpadding characters retain all their text. Longer results are split at paragraph gaps and Tavily's `[...]` markers. Clear product/version support statements and matching organization/role paragraphs receive priority; other claims use lexical overlap. Explicit support patterns include `Python 2 is currently supported` and negative/no-longer variants. Role anchors reuse the existing narrow English role parser. An alternative holder can be relevant: the original claim's person's name is not required. These are limited English heuristics, not universal relevance or entailment detection.

The selected text is an exact contiguous substring. Neighboring paragraphs are included when the whole span fits the 1,200-character limit. Paragraphs are not rewritten, combined from separate locations or reduced to positive-looking clauses. An oversized selected paragraph is clipped with an exclusion warning rather than silently treated as complete. If other potentially relevant paragraphs lie outside the selected span, or only the first 20,000 characters could be inspected, a warning requires fuller review. Context in a separate unrecognized passage can still be missed: an anchor match never proves the absence of qualifications or conflicts elsewhere on a page.

Each newly retrieved source includes optional `excerptSelection` metadata: UTF-16 start/end offsets, total returned-text length, selection reason and any warning. Offsets refer to the original Tavily result content, not to full page HTML or rewritten text. Short text preserves leading/trailing-trim bounds. The server's raw search cache still permits claim-specific selection without a second search. Metadata does not independently authenticate source wording; full page retrieval is not added.

Comparison independently checks package-list dominance and matching product/version support context. A support claim cannot count a general library-compatibility excerpt without an explicit matching product/version. These checks do not infer truth or turn missing mentions into contradiction. Excerpts with quality/selection warnings remain visible but are ineligible for corroboration. Fewer than two remaining source groups causes inconclusive before inference; no correction is invented. The website shows selection notes/warnings alongside existing source dates and comparison warnings.

Within current-scope results, sources without quality warnings are ordered first; the existing captain-appointment priority is used within equal quality tiers. `as_stated` retains search-result order. All usable sources up to the existing three-result cap are retained, including weak context. This ordering neither proves official ownership nor treats relevance as support. Dates continue to be checked against the original returned text before excerpt selection.

The original saved Python search excerpts contain a package list, generic Google Cloud compatibility text and one explicit end-of-life statement. Offline replay now excludes the first two before inference while preserving all three citations. It cannot recover text missing from those already-truncated saved excerpts or manufacture a second corroborating source. The replay is separately saved as `.local/live-website-check/excerpt-quality-review.json`; original live reports are unchanged. A synthetic raw result with a useful paragraph beyond the old cutoff demonstrates selection mechanics, not a measured live retrieval improvement.

Validation on November 4, 2026 passed all 448 unit/API tests across 34 files using one worker, all 16 desktop/mobile browser checks, lint, TypeScript, six fixture regressions, production build and offline API smoke checks. Fifteen new cases cover passage selection, exact substring offsets, preserved qualifiers, oversized/conflicting context warnings, package identifiers, version mismatch, alternate role holders, bounded inspection, cache reuse and pre-inference abstention. No Gemini or Tavily requests were made and saved `.env` settings were unchanged.
