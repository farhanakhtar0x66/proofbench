## What exists on this branch

| Area | Where to start |
| --- | --- |
| UI and user flow | [`TrackDBench.tsx`](../apps/web/src/TrackDBench.tsx) is mounted in the Execution Lab. It selects mode, task, repeats, and fault, then shows progress, pass counts, individual trials, trace playback, source diff, gateway receipts, and evidence JSON. Agent explanations can be sent to the existing Freshness Verifier. [`main.tsx`](../apps/web/src/main.tsx) wires navigation and verifier handoff. [`style.css`](../apps/web/src/style.css) carries the layout and animation. |
| API and data | [`track-d.ts`](../apps/api/src/track-d.ts) registers `GET /api/track-d`, `POST /api/track-d`, and `GET /api/track-d/:id`. It permits one active session per API process and persists sessions with the existing JSON store. [`Track D contracts`](../packages/contracts/src/track-d.ts) define the API payloads and trial verdicts. |
| Session runner | [`session.ts`](../implementations/bifrost-02/src/track-d/session.ts) alternates agent order across repeats, assigns the same generated seed within each pair, grades each final submission, and publishes trial records. It records source SHA-256, diff, time to verdict on newer runs, and gateway telemetry when observed. |
| Agents and relay | [`agents.ts`](../implementations/bifrost-02/src/track-d/agents.ts) contains the fixed-model ProofBench JSON edit loop and the OpenCode CLI adapter. [`gateway.ts`](../implementations/bifrost-02/src/track-d/gateway.ts) routes both to local Bifrost and checks provider/model receipts. The defaults are six model attempts, up to 3,500 output tokens per request, and 150 seconds for the agent. |
| Grader and baseline | [`grader.ts`](../implementations/bifrost-02/src/track-d/grader.ts) provides the `distance-width` and `directed-edges` tasks, a public check, hidden edge cases, and a seeded graph. The C++ solver runs in Docker or WSL bubblewrap. The host runs the [pinned Python oracle](../fixtures/track-d/oracle/d_traverse.py) and compares exact output bytes. [`track-d-baseline.ts`](../scripts/track-d-baseline.ts) reads Team Lex's solver from a fixed Git commit. |
| Tests | [`track-d.test.ts`](../tests/track-d.test.ts) covers the relay and, when enabled, actual worker grading. The existing API and Playwright suites cover the shared app. |

- **Live clean pilot.** `58065a0e-b4ce-4edc-b75b-dc615610af2e` ran one `distance-width` pair with `ollama/qwen3:1.7b` and WSL GCC 15.2. Both agents had five observed gateway calls, with matching provider/model receipts. ProofBench used 3,056 input and 9,696 output tokens and submitted C++ that failed to compile. The wide-path example expected `4294967295` and got `-1`. The session's `comparable: true` means the gateway evidence satisfied the current comparability rule. ## First run on a new checkout

1. Install Node.js 22.12 or newer, npm dependencies, Python 3, Git, and a worker. Docker uses a locally available `gcc:15` image by default. Windows can set `TRACK_D_WORKER=wsl` with the Ubuntu WSL distro, GCC, and bubblewrap. See [the setup guide](TRACK-D-BENCHMARK.md) for alternate executables and the Team Lex command.
2. Run `npm ci` and `npm run dev` from the repo root. Vite uses port 5173 and proxies to the API on 3001. Open `http://127.0.0.1:5173/#track-d`, choose **Offline fixtures**, and start a clean session. If you have a local record, `/?trackSession=<id>#track-d` opens it, and `GET /api/track-d/<id>` returns its JSON.
3. To reproduce the live pilot, run local Ollama with `qwen3:1.7b` and Bifrost on `http://127.0.0.1:8089`, using a virtual key scoped to that provider/model. The local pilot used OpenCode CLI 1.19.5. In the API environment set `TRACK_D_LIVE=true`, `TRACK_D_BIFROST_MODEL=ollama/qwen3:1.7b`, `BIFROST_GATEWAY_URL`, `BIFROST_VIRTUAL_KEY`, and `TRACK_D_OPENCODE` to an absolute executable path. Check Bifrost health before the run. Local processes and temporary configs from the last session may need restarting.
4. Run `npm run lint`, `npm run typecheck`, `npm run build`, and `npm run test:ui` for affected surfaces. Run `npx vitest run tests/track-d.test.ts` for the relay tests and set `TRACK_D_TEST_GRADER=true` with a working worker to include the real grader. For separate Tavily testing, check `/api/analysis/readiness` first. Live retrieval requires the existing Tavily key, explicit live-request consent, and a positive request budget.
