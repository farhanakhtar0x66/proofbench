# General analysis in the website

The general flow now discloses [five-minute comparison-cache reuse](COMPARISON-CACHE.md), expiry and original assessment time. A repeated request can avoid another comparison call; optional LLM claim extraction is not cached.

Run `npm run dev` to start the Fastify backend and Vite website together. Open the local website, select **Freshness verifier**, keep **General claim analysis**, and enter factual assertions. The page submits one `POST /api/analysis`, not separate client-orchestrated searches or comparisons. Up to three distinct extracted statements are processed; omitted claims and fallback extraction are disclosed.

The **Evidence scope** selector defaults to current evidence. Most current queries use the existing 30-day publication filter; [recognized support-status claims](SUPPORT-SEARCH.md) retrieve older documentation without that filter. Per-result search-window text discloses which plan ran. **Search the statement as written** selects `as_stated`; neither option disables comparison's existing date checks. General analysis is the default. **Legacy verifier / fixture demo** preserves the older `/api/verify` flow, including labeled offline fixture demonstrations such as Python 2. In live server mode that legacy route uses its existing live controls; selecting it does not force the server offline.

Each finding displays supported/contradicted/inconclusive, freshness, explanation, source links and full retained excerpts, provider publication/update estimates, retrieval timestamps, eligibility/date/scope warnings and any validated source-backed correction. Supported current results can show an [evidence-recency score](EVIDENCE-FRESHNESS.md) with its explanation; other results remain unscored. Sources excluded from corroboration remain visible. Scores and statuses are not calibrated truth probabilities.

The page reads `GET /api/analysis/status` to show the backend source mode, extraction/comparison configuration and whether the interpreter's configured allowance/cooldown permits requests. This endpoint only reads local configuration; it makes no gateway/provider request and never returns API keys. It is not a gateway health check, billing verification or account quota inspection. Mode is refreshed after submitting. A configured live mode does not bypass consent, keys, shared server caps or cooldowns.

Saved `.env` defaults remain rules/mock and caps zero. Under those defaults, general statements are inconclusive with offline explanations and no invented sources. Merely running the website does not enable live verification. No new live budget is authorized by this integration. Provider selection and keys remain server-side; there is no browser key-entry form or provider switch in this change. Frontend-only `VITE_API_MODE=mock` still supports the legacy fixture display; general analysis explains that the backend is required.

While a submission is pending, editing, duplicate submission and workspace navigation are disabled. A status message describes the non-streaming operation; it does not invent live progress for individual stages. Analysis waits up to 180 seconds instead of the old 15-second client deadline. No automatic retry is made. If the connection drops or the client wait times out, the backend may still finish: check before resubmitting. Active backend cancellation and server-wide usage persistence remain separate work.

Browser tests run API/web on separate local ports (3011/5181) so they do not reuse or stop the developer's normal 3001/5173 servers. All provider/Tavily access is explicitly disabled by their environment. `API_PROXY_TARGET` configures only Vite's server-side test proxy; the normal proxy target remains port 3001. Desktop/mobile cases cover the real offline analysis API, all three verdict displays with simulated evidence, source dates/warnings, correction presentation, omissions, zero claims, pending/error states and existing legacy fixtures.

After the final client-error wording and status-endpoint assertion changes, lint, types, the affected API suite and build passed again; browser checks exercised the revised error message.
